# 部署攻略

页面做好之后要放到网上，别人才能扫码打开。这一步有三条路，**从零成本开始，
确认效果再决定要不要投入**。

## 先回答三个问题

```
① 只是想先看看效果？
   → GitHub Pages。零成本、10 分钟、不需要备案

② 要发到微信群里给国内的人看？
   → 必须有「已备案的域名」。这是国内法规要求，绕不过去
   → 域名 + 对象存储，一年几十块

③ 以后还要做很多个页面、需要看访问日志？
   → 云服务器 + Caddy，一个月几十块
```

**关键提醒：备案需要 7–20 天，要本人实名、上传证件、视频核验。**
这件事没有任何 AI 或工具能替你完成。如果活动就在两周内，
先走 GitHub Pages 应急，同时开始备案流程。

---

## 路线一：GitHub Pages（零成本，先看效果）

适合试水、内部预览、或者受众不在国内。国内也能打开，只是慢一些（首次加载 2–5 秒）。

### 步骤

1. **注册 GitHub 账号**（github.com，免费）
2. **新建仓库**：点右上角 `+` → `New repository`，名字随便起，
   **Public**（公开），勾选 `Add a README file`
3. **上传文件**：进仓库点 `Add file` → `Upload files`，
   把 `deck.html` 拖进去，**改名为 `index.html`**（这一步很关键，
   不改名的话地址后面要带文件名）。有 `bgm.mp3`、`qr.png` 一起传
4. **开启 Pages**：仓库页 `Settings` → 左栏 `Pages` →
   Source 选 `Deploy from a branch`，Branch 选 `main` / `(root)` → `Save`
5. **等 1–2 分钟**，刷新这个页面，顶部会出现网址，形如
   `https://你的用户名.github.io/仓库名/`

那个网址就是详情页地址。把它填进 `templates/poster.html` 的 `DETAIL_URL`，
重新出海报，二维码就指向它了。

### 局限

- 国内访问偏慢，弱网下首屏可能要等几秒
- 网速不稳时字体可能加载失败，中文会退成系统字体（不影响阅读，但排版不如原样）
- 不适合正式的大范围传播

## 路线二：对象存储 ＋ 备案域名（国内传播，推荐）

一年成本大约几十元。国内访问快，这是正式传播该用的方案。

### 第一步：买域名并备案

1. 在阿里云 / 腾讯云 / 华为云任选一家买域名（`.com` / `.cn` 一年几十元）
2. **立刻开始备案**，在同一家的"备案"控制台提交：
   - 需要：身份证、手机号、一个该服务商的云资源（买了对象存储或服务器就有）
   - 流程：填资料 → 服务商初审（1–3 天）→ 工信部审核（3–20 天）
   - 期间会有一次**视频核验**或人脸识别，必须本人做
3. 备案通过后会拿到一个备案号，要放在页面底部

**这一步是整个流程里唯一的硬门槛。** 没有备案，域名在国内服务器上无法提供访问。

### 第二步：开对象存储

以阿里云 OSS 为例（腾讯云 COS、七牛云同理）：

1. 控制台搜"对象存储"→ 创建 Bucket
   - 读写权限选 **公共读**
   - 地域选离受众近的（华北/华东）
2. 上传 `index.html`、`bgm.mp3`、`qr.png` 等文件
3. 在 Bucket 的"基础设置"里开启 **静态网站托管**，默认首页填 `index.html`
4. 在"传输管理"→"绑定域名"里绑定你的**已备案**域名

### ⚠️ 一定会踩的坑

**用对象存储的默认域名（`xxx.oss-cn-beijing.aliyuncs.com`）访问 HTML，
浏览器会直接下载文件而不是显示网页。**

这是各家云厂商的统一策略，防止有人拿对象存储当免费网站空间。
解决办法只有一个：**绑定已备案的自定义域名**。

所以顺序是：先备案 → 再绑域名 → 才能正常访问。别在没备案的时候
反复调试为什么打不开，那不是你配置错了。

## 路线三：云服务器 ＋ Caddy（进阶）

适合要做很多个页面、想要访问日志、或者以后要接表单接口的情况。
一个月几十元起。

### 为什么用 Caddy 而不是 Nginx

Caddy 自动申请和续期 HTTPS 证书，配置文件只有几行。Nginx 要手动配 certbot，
对不熟悉运维的人来说是不必要的负担。

### 配置

```caddyfile
# /etc/caddy/Caddyfile
your-domain.example.com {
    encode gzip
    root * /srv/deck
    file_server

    # HTML 每次回源验证：改完上传立刻生效。
    # 不设的话浏览器按自己的规则缓存，你改了页面，别人看到的还是旧版 ——
    # 活动当天没法让一百个人清缓存。
    @page not path *.png *.jpg *.jpeg *.webp *.svg *.ico *.woff2 *.css *.js *.mp3
    header @page Cache-Control "no-cache, must-revalidate"

    # 图片、字体、音频极少变动，给一个月
    @asset path *.png *.jpg *.jpeg *.webp *.svg *.ico *.woff2 *.mp3
    header @asset Cache-Control "public, max-age=2592000"

    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        X-Content-Type-Options "nosniff"
        -Server
    }
}
```

生效：

```bash
mkdir -p /srv/deck
caddy validate --config /etc/caddy/Caddyfile && systemctl reload caddy
```

上传页面：

```bash
scp index.html bgm.mp3 qr.png root@你的服务器IP:/srv/deck/
```

### ⚠️ 加新站点时的坑

如果 Caddyfile 里给新站点配了独立日志文件，`reload` 会失败并报
`permission denied` —— Caddy 以非 root 用户运行，日志目录得让它能写：

```bash
chown -R caddy:caddy /var/log/caddy
```

`reload` 失败时 Caddy 会保留旧配置继续运行，现有站点不受影响，可以从容排查。
但要养成习惯：**先在副本上 `caddy validate`，通过了再替换正式配置**。

## 上线后必做的检查

用**手机流量**（不要连 WiFi，避免走公司网络）在微信里打开一次：

- [ ] 页面能正常打开，不是证书错误页
- [ ] 中文标题是宋体等预期字体，不是系统默认字体（说明字体加载成功）
- [ ] 每一屏都不用下拉就能看全
- [ ] 一次滑动只翻一页
- [ ] 有背景音的话，打开就出声，音符键能关能开
- [ ] 二维码扫出来落在正确的地址

海报发出去之前，**务必用另一部手机扫一次海报上的二维码**，确认落点。

## 常见报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 点开链接自动下载文件 | 用了对象存储的默认域名 | 绑定已备案的自定义域名 |
| 微信里提示"已停止访问该网页" | 域名被举报或未备案 | 换域名；备案；用短链中转 |
| 页面能开但字体是系统默认 | Google Fonts 被拦或加载超时 | 把字体文件下载到自己服务器，改本地引用 |
| 改了页面但打开还是旧的 | 缓存 | 按上面的 Caddy 配置给 HTML 设 `no-cache` |
| 证书错误 / 无法建立安全连接 | DNS 还没生效就配了 HTTPS | 等 DNS 解析生效（几分钟到几小时）再重试 |

## 关于短链

如果海报要印刷、或者要发到大量群里，**让二维码指向一个自己可控的短链**，
再由短链跳转到详情页。这样以后换域名、改地址、加统计，都不用重做海报。

海报一旦发出去，二维码就锁死了 —— 这是唯一不可回滚的一步。
